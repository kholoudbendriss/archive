# Полное руководство: Создание своего ImGui / UMG Меню в Lua с нуля для PUBG Mobile

В мобильных играх на движке Unreal Engine (включая PUBG Mobile) интерфейс строится на системе **UMG (Unreal Motion Graphics)** через язык Lua.

Вместо стороннего C++ ImGui, мобильные читы и моды создают интерфейс напрямую через нативные классы движка. Это даёт 60-90 FPS без лагов, поддержку сенсорного экрана и полный контроль над цветами, прозрачностью и формами.

Готовый рабочий файл со структурой `BP_Player` / `BRPlayerCharacterBase`: **[custom_imgui_menu.lua](file:///C:/Users/smofe/Documents/PackTools/custom_imgui_menu.lua)**.

## 1. Как PUBG Mobile запускает Lua-скрипт (BP_Player / BRPlayerCharacterBase)

В игре главным скриптом игрока является **`BRPlayerCharacterBase.lua`** (соответствует игровому актору `BP_PlayerPawn`).
Когда матч загружается и ваш персонаж появляется на карте:

1. **Игровой класс**:
   Движок инициализирует класс персонажа:
   ```lua
   local BRPlayerCharacterBase = {
       ServerRPC = {},
       ClientRPC = {},
       MulticastRPC = {},
       LuaEventContainer = {}
   }
   ```
2. **Точка входа (`_PostConstruct`)**:
   Движок вызывает метод жизненного цикла:
   ```lua
   function BRPlayerCharacterBase:_PostConstruct()
       BRPlayerCharacterBase.__super._PostConstruct(self)
       -- Здесь стартует наш хук и поиск Canvas
   end
   ```
3. **Холст экрана (`InGameUITools.GetMainControlBaseUI()`)**:
   Чтобы меню не висело в воздухе, оно крепится к главному слою игрового интерфейса — `CanvasPanel_0`:
   ```lua
   local InGameUITools = require("GameLua.Mod.BaseMod.Common.UI.InGameUITools")
   local MainUI = InGameUITools.GetMainControlBaseUI()
   local canvas = MainUI.CanvasPanel_0
   ```
4. **Таймер ожидания (`common.time_ticker`)**:
   Поскольку экран и кнопки управления загружаются не мгновенно, используется цикличный таймер, который ждёт появления `CanvasPanel_0`:
   ```lua
   local ticker = require("common.time_ticker")
   ticker.AddTimerLoop(1.0, function()
       if not _initDone then
           TryInit()
       end
   end, 0, 1.0)
   ```

## 2. Базовые кирпичики (Виджеты Unreal Engine UMG)

Любое меню собирается всего из 4 типов объектов:

| Виджет в UE | Для чего используется в меню |
|---|---|
| `/Script/UMG.CanvasPanel` | Главный контейнер окна с абсолютными координатами X, Y |
| `/Script/UMG.Border` | Прямоугольники, цветные фоны, рамки, тени, разделители, треки слайдеров |
| `/Script/UMG.TextBlock` | Любой текст (названия, цифры, значения слайдеров) |
| `/Script/UMG.Button` | Невидимая область поверх слоя, перехватывающая клик/тап игрока |

## 3. Цвета в Unreal Engine (FLinearColor)

В движках UE цвет задаётся не от `0` до `255`, а **от `0.0` до `1.0`**:
* **R (Red)**: Красный
* **G (Green)**: Зелёный
* **B (Blue)**: Синий
* **A (Alpha)**: Прозрачность (1.0 = плотный, 0.5 = полупрозрачный, 0.0 = невидимый)

### Формула перевода HEX / RGB в UE:
`Значение / 255`

```lua
-- Главный темный фон окна
local bg = FLinearColor(0.07, 0.09, 0.14, 0.96)

-- Неоновый синий (#2e80ff -> 46, 128, 255)
local blue = FLinearColor(46/255, 128/255, 255/255, 1.0) -- (0.18, 0.50, 1.00, 1.0)

-- Ярко-красный для кнопки закрытия [X]
local red = FLinearColor(0.92, 0.22, 0.25, 1.0)
```

## 4. Порядок слоёв (Z-Order)

Чтобы фон не перекрывал кнопки и текст, используется параметр **Z-Order**:
* Чем выше число Z-Order, тем выше слой (находится поверх остальных).

```
Слой 50:    Кнопка перехвата клика (Z-Order = 50)
Слой 15:    Текст и цифры (Z-Order = 15)
Слой 12-14: Переключатели, бегунки, кнопки [-] [+] (Z-Order = 12-14)
Слой 10:    Фон строки (Z-Order = 10)
Слой 2:     Главный фон окна (Z-Order = 2)
Слой 1:     Неоновая обводка (Z-Order = 1)
```

## 5. Как устроены компоненты управления

### 1) Чекбокс / Тумблер (Вкл / Выкл):
1. `Border` — плашка строки.
2. `TextBlock` — название функции.
3. `Border` справа (трек тумблера) + маленький квадрат (бегунок).
4. `Button` поверх строки:
   * При клике инвертирует переменную: `Config[key] = not Config[key]`
   * Меняет цвет трека (синий / серый)
   * Сдвигает бегунок вправо или влево

### 2) Слайдер с кнопками [-] и [+]:
1. Строка с названием функции.
2. Текст текущего числового значения.
3. Две кнопки `[-]` и `[+]`:
   * Клик на `[-]` уменьшает значение до `minVal`.
   * Клик на `[+]` увеличивает значение до `maxVal`.
   * Текст `valText:SetText(...)` мгновенно обновляется.

### 3) Вкладки (Tabs):
Вместо кучи отдельных окон создаётся один контейнер `contentContainer`.
При клике на вкладку (`VISUALS`, `AIMBOT`):
1. Очищаются старые элементы: `contentContainer:ClearChildren()`
2. Вызываются функции отрисовки нужных чекбоксов и слайдеров для выбранной вкладки.

## 7. Как сделать перемещение пальцем по экрану (Drag & Drop)

В UMG виджеты перемещаются через их слот в Canvas: `slot:SetPosition({ X = newX, Y = newY })`.

### Принцип работы перетаскивания:

1. **Группировка в CanvasPanel**:
   Чтобы не двигать каждый прямоугольник и текст по отдельности, вся плавающая кнопка помещается внутрь одного маленького `CanvasPanel` (`floatContainer`). Перемещая только этот контейнер, всё содержимое перемещается вместе с ним.

2. **Получение координат тача (пальца)**:
   Через контроллер игрока `PlayerController`:
   ```lua
   -- Touch 0 — первый палец на экране
   local x, y, isPressed = pc:GetInputTouchState(0, 0, 0, false)
   -- Или для эмуляторов ПК:
   local mx, my = pc:GetMousePosition(0, 0)
   ```

3. **События кнопки (OnPressed / OnReleased)**:
   * **`OnPressed`** (палец коснулся экрана):
     Запоминаем начальные координаты пальца (`dragStartTouchX, dragStartTouchY`) и текущую позицию кнопки.
   * **Тикер (50 FPS)**:
     Пока палец зажат, считаем сдвиг: `deltaX = currentTouchX - startTouchX`.
     Если `deltaX > 4` px — палец двигается, значит обновляем позицию:
     `floatContainer.Slot:SetPosition({ X = startPosX + deltaX, Y = startPosY + deltaY })`
   * **`OnReleased`** (палец оторвался от экрана):
     Сбрасываем флаг `isDragging = false`.
     **Умная проверка**: если палец НЕ сдвигался (был просто короткий тап на месте) — срабатывает открытие/закрытие меню! Если палец тащили — клик не вызывается.

4. **Перетаскивание самого окна меню**:
   Точно такой же невидимый слой кнопки накладывается на шапку окна (`Header`). При зажатии шапки всё окно плавно передвигается в любую точку экрана.

## 8. Как сразу протестировать в игре

Файл **`custom_imgui_menu.lua`** уже готов для использования в игре:
1. Чтобы проверить его в игре, переименуйте или скопируйте его как:
   `PAK TOOL\EDIT\Content\Lua\GameLua\Mod\BRMod\Gameplay\Core\BRPlayerCharacterBase.lua`
2. Запакуйте `.pak` через ваш `tool.py` / `PAK TOOL`.
3. Запустите игру и зайдите в кастомку/тренировку.
4. Вверху экрана появится аккуратная кнопка **`[OPEN MENU]`**.
5. Теперь её можно **свободно перетаскивать пальцем** в любое удобное место экрана!
6. А по обычному нажатию откроется само меню, которое также можно перетаскивать за шапку!
